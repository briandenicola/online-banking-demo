## Diagnosis

All services connecting to Azure Managed Redis were failing with "Connection reset by peer" on port 10000. DNS resolution from inside AKS pods was returning the **public IP** (4.172.66.86) instead of the private endpoint's private IP (10.220.4.13).

**Root Cause:** Wrong private DNS zone in Terraform. `infra/cloud/private-endpoints.tf` used `privatelink.redisenterprise.cache.azure.net` (for old Azure Cache for Redis Enterprise) instead of `privatelink.redis.azure.net` (for Azure Managed Redis / `azurerm_managed_redis`). The private endpoint's A record could not auto-register in the wrong zone, so DNS queries returned the public endpoint (which has public access disabled → connection reset).

## Resolution

1. **Corrected DNS zone** in `infra/cloud/private-endpoints.tf` from `privatelink.redisenterprise.cache.azure.net` to `privatelink.redis.azure.net`.

2. **Applied via az CLI incrementally:**
   - Created new correct DNS zone
   - Linked VNet to new zone
   - Updated PE DNS zone group to point to new zone
   - Deleted obsolete old zone

3. **Verified:** DNS from pod now resolves to PE private IP 10.220.4.13; TCP to port 10000 succeeds.

## Pattern Note

Azure has THREE Redis products with different private endpoint DNS zones:
- Azure Cache for Redis (standard/premium): `privatelink.redis.cache.windows.net`
- Azure Cache for Redis Enterprise (old): `privatelink.redisenterprise.cache.azure.net`
- Azure Managed Redis (new): `privatelink.redis.azure.net` ← This one

Always cross-reference the [Azure PE DNS zone table](https://learn.microsoft.com/en-us/azure/private-link/private-endpoint-dns).
