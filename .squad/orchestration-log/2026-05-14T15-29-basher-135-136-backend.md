## Summary

Basher implemented backend for #135 and #136:

**Schema Extensions:**
- `LastError` model: stage, code, message, retryable, occurredAt, attempt, correlationId
- `ApplicationResponse` extended: lastError, stageAttempts, failedStage, customerOutcome, customerExplanation, customerExplanationGeneratedAt
- `ApplicationStatus` enum: added `failed` state

**Repository Methods:**
- `record_stage_failure(application_id, stage, error)` — persists error + increments stageAttempts
- `clear_stage_failure_for_retry(application_id, stage)` — clears error, sets status back to stage
- `set_customer_explanation(application_id, outcome, explanation)` — stores AI-generated text

**Consumer Base Class Idempotency:**
- `_derive_idempotency_key(app_id, attempt)` → `{applicationId}:{stage}:{attempt}`
- `_is_already_processed(key)` — Redis SET check with 24h TTL
- `_mark_processed(key)` — Redis SET with SADD + EXPIRE

**Error Classification:**
- `_classify_error(exc, stage, attempt)` → `LastError`
- Maps exceptions to: timeout, auth_error, validation_error, connection_error, unknown_error
- Sets `retryable` flag

**Resubmit Endpoint:**
- `POST /api/account-opening/applications/{id}/resubmit`
- Pre-conditions: status == "failed", lastError.retryable == true, stageAttempts[failedStage] < 2
- Response (202 Accepted): { applicationId, resumedFromStage, attempt, status, message }
- Error (409 Conflict): { error: "retry_cap_exceeded", message: "..." }

**Customer Explanation Generation:**
- Provisioning stage calls `_generate_customer_explanation()` at finalization
- Maps decision → customerOutcome (approved/declined/needs_review)
- Generates 2-3 sentence friendly explanation via Foundry agent
- Stores via `set_customer_explanation`
- Non-blocking on provisioning success
