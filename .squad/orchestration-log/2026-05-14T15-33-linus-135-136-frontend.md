## Summary

Linus implemented frontend for #135 and #136:

**Component Architecture:**
- Extracted `ApplicationStages.tsx` as shared component (147 lines) for both admin and customer views
- `AgentPipeline.tsx` refactored from 147→47 lines using shared component
- `CustomerApplicationStatusPage.tsx` created (283 lines) with polling + retry UX

**Retry Button Logic:**
- Visible only when: status === 'failed' AND lastError?.retryable === true AND stageAttempts?.[failedStage] < 2
- Implements retry cap per Brian's directive (max 1 retry = 2 total attempts)
- Edge case: stageAttempts dict may not contain key; defaults to 0

**AI Explanation Display:**
- Renders customerExplanation ONLY for terminal statuses (approved/rejected/pending_review/failed)
- One-shot generation at finalization (never regenerated)
- Visual design: approved (green), rejected (red), pending review (yellow), failed (neutral)

**Polling Strategy:**
- 2s interval until isTerminal(status) returns true
- useEffect cleanup prevents memory leak on unmount
- useRef prevents stale closure issues

**Error Handling:**
- Uses `resolveApiError()` helper for all API calls
- Handles FastAPI 422 validation arrays (coerces to human-readable strings)
- 409 conflict: display backend message, hide retry button

**MUI v9 Icon Choice:**
- Uses ErrorOutlineRounded (v9 removed ErrorOutline)

**Routing:**
- Redirect to `/applications/:id/status` after document upload
- Enables bookmarking, sharing, cleaner separation of concerns
