## Key Design Decisions

1. **Agent Consumer Pattern:** Each consumer extends AgentConsumer base class; implements process_event() for specialized logic
2. **Stream Chaining:** Output of one agent becomes input to next (document → identity → compliance → provisioning)
3. **Worker Initialization:** Init container creates Redis Streams consumer groups before workers start
4. **Graceful Shutdown:** Worker handles SIGTERM and cancels all consumer tasks
5. **Concurrent Processing:** All 4 agents run concurrently in worker Pod; each reads from its assigned stream
6. **Kubernetes Integration:** Kustomize manifest with init containers, ConfigMaps, liveness/readiness probes

---

## Integration Points

1. **State Machine:** Agent consumers update application state via state_machine.transition()
2. **Event Publishing:** Consumers publish intermediate results to next agent's stream
3. **Redis Streams:** Supports consumer groups, ACKing, claim timeout recovery
4. **Configuration:** All agent settings injected via environment/ConfigMap
5. **Authentication:** Agents inherit JWT validation from app.auth
