## What Was Done

**Root Issue:** Previous deploy used `sed` to mutate kustomize manifests in place, then reverted after build. This pattern:
- Mutates committed files (Git sees dirty state)
- Requires manual cleanup on failure
- Couples deployment config to pipeline script

**New Pattern (stream-substitute):**
- Read manifest → substitute env vars via stream → pass to `kustomize build` via stdin/pipe
- No file mutations
- Clean separation: Terraform outputs (source of truth) → stream substitution → Kustomize build
- Aligns with Brian's "Convention over Configuration" directive (never persist env-specific values in committed manifests)

**Files Changed:** Deploy pipeline script (exact path in decision drop).

## Design Principle
All hardcoded environment-specific values (ACR names, tags, endpoints) must be DRIVEN from Terraform state at deploy time, never persisted in committed manifests. Repeated drift bugs (ghost ACR names, committed substitution values) all violate this principle.
