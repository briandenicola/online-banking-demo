## What Was Done

### Bug A — FastAPI Serialization of EvalResults (ai-service)
**File:** `src/ai-service/app/routes/api.py`

When returning agent-framework-foundry SDK's `EvalResults` object from FastAPI:
- SDK object has `total`, `passed`, `failed`, `all_passed` as `@property` methods, NOT dict attributes
- FastAPI's serializer only includes `__dict__`, NOT `@property` computed fields
- Downstream C# parser crashed with `KeyNotFoundException` looking for missing top-level fields

**Fix:** Manually flatten EvalResults to plain dict with all expected top-level fields before returning.

### Bug B — Incomplete Eval Success (ai-service)
**File:** `src/ai-service/app/routes/api.py`

Foundry SDK's `_poll_eval_run()` polls until completion OR timeout (180s default). If timeout/failure:
- Returns with `status in ("timeout", "failed", "canceled")`, NOT exception
- ai-service was logging "ok" and returning ANY result without checking `status=="completed"`
- C# received sparse/incomplete results and failed parsing

**Fix:** Check `results.status == "completed"` before logging success; raise HTTPException(500) otherwise.
