### 1. PolicyVersion Derivation — Content Hash of RESOLVED Policy (§6.2.1)

Format: `pv1:<sha256[:16]>`. Recommended over hand-maintained semver for:
- **(a)** Cannot be forgotten on edit — version IS the content
- **(b)** Covers env-var overrides (the non-obvious one) — ConfigMap threshold edits are real policy changes with byte-identical YAML file. Every threshold env-overridable here. Hash of file alone misses this entirely.
- **(c)** Deliberately not ordered — nobody can write `if version > signed_version` and reintroduce forbidden temporal special-casing

Placement in canonical preimage (§6.2 rule 9): in **domain-separation prefix** after `action_id`, not as key inside projected object. Faithful to "alongside action type"; `action_id` lives in prefix. Avoids collision with literal `policyVersion` payload field; keeps projection meaning "business facts human agreed to." Scheme tag bumped `bcp.v1` → `bcp.v2`, `canonicalizationVersion` `1` → `2`. Nothing in flight, no migration needed.

### 2. Execution-Time Re-Evaluation (§3.6)

`authorize_execution()` pseudocode with void path, reusing same `evaluate()` and `RUNG_ORDER` as §3.4. Deliberately no `else` branch adjusting on loosened path — loosened policy is not an event. Includes Brian's $40k-loan worked example as canonical doc/UI copy.

**Critical implementation detail** (§6.4): **Hash recompute uses policy version STORED on approval; rung re-evaluation uses CURRENT one.** If hash recompute used current version, every policy edit (including comment reflow) would fail hash comparison for every pending approval — directly contradicting ruling clause 3. Signature verification is archaeology; authority is live. They must not share an input. Documented as two-row table, cannot be skimmed past.

### 3. Narrowed Blast Radius (§6.6)

Narrow *because* we key off re-evaluated rung, not version inequality. Cosmetic edits and policy *loosening* void nothing. Only approvals whose payload crosses newly-tightened value affected. Keying off version inequality would nuke every pending approval on every edit — called out twice on purpose.

### 4. Operations — Eager Notification, Lazy Correctness (§6.6)

Eager void sweep on reload for *notification*, with lazy execute-time check as *correctness guarantee* — same separation as expiry design (§5.4). New `POST /api/copilot/policy/impact` (§8.10) dry-runs candidate policy and returns exactly which approvals would void and why. **Warns, never blocks** — gating policy tightening behind pending work runs incentive backwards.

### 5. No Bulk Re-Sign

Re-proposal may be initiated in bulk; signing may not. A "re-approve all 40" button would reconstitute blanket approval by back door at moment of maximum approval fatigue (R3). Worst possible time to offer one click.

### 6. Audit — Full Provenance (§7.2)

`ApprovalVoidedByPolicyChange` carries `discardedSignatures[]` in full. "Machine discarded human's signature" is exactly what incident review will ask about; must not be reconstructible by inference alone. Plus `PolicyReloaded` with version transition and affected count.

## Self-Correction on Q1

My standing recommendation: **"void if rung would change"** — symmetric. The ruling is asymmetric, and asymmetric is right:
- Voiding on downward change punishes banker for policy *relaxation*
- Generates pointless re-signing churn
- Signature given was for strictly *more* scrutiny than now required — safe by construction

I pattern-matched to "any drift invalidates" instead of deriving from monotonic principle already in I-4. **When new rule feels like its own shape, check whether existing invariant already generates it.** Failure mode is reusable; recorded because lessons are.

## Discovered Hang-Togethers

**No new lifecycle state.** Policy-voiding persists as `denied` + `terminalReason = "policy_change"`, matching how supersede-by-re-plan works, rather than inventing `voided` state outside ratified `proposed → pending → signed | denied | expired`. "Voided" is presentation label. **Raised as O9** — first-class `voided` state arguably cleaner for auditors, is cheap, Danny's call.

**New risk surfaced by split:** approval store written by .NET, read by Python. Cosmos field paths case-sensitive; serializer mismatch returns zero rows, not error. Added mandatory round-trip test to CI list (§10, item 8).

**O10 (new):** wiring `/policy/impact` into CI as required check tempting but runs against empty approval store, always reports zero impact — false confidence, worse than no check. Ship endpoint for operators; defer the gate.
