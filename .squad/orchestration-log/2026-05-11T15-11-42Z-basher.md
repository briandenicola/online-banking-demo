# Orchestration Log: Basher — Event Processor Pod Failure (Istio Sidecar Blocking Redis TLS)

**Agent:** Basher (Backend Dev)  
**Mode:** background  
**Status:** ✅ Fixed

## Diagnosis

Event-processor pod was crash-looping on AKS. Investigation revealed **ALL 5 Redis-using services** failing to connect to Azure Managed Redis:
- event-processor (Go)
- transaction-service (C#)
- user-service (C#)
- transfer-service (C#)
- ai-service (Python)

**Root Cause:** Istio Envoy sidecar was intercepting outbound TLS traffic to port 10000 and breaking the Redis TLS handshake (ECONNRESET). The sidecar attempts to re-encrypt already-encrypted Redis traffic, causing the connection to drop.

## Resolution

1. **Added `traffic.sidecar.istio.io/excludeOutboundPorts: "10000"` annotation** to all 5 pod templates connecting to Azure Managed Redis. This bypasses Istio's Envoy proxy for Redis traffic while keeping all other traffic within the mesh.

2. **Restructured event-processor health/retry logic:**
   - Start HTTP health server **before** attempting Redis connection (doesn't block startup)
   - Report readiness based on actual Redis state
   - Retry indefinitely instead of crashing after 10 attempts
   - Allows graceful degradation if Redis is temporarily unavailable
