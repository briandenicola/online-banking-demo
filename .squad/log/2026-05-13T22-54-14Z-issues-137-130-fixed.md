## Summary

Brian asked the Basher agents to debug two persistently-befuddling issues. Both were fixed:

1. **#130 (Redis-backed AI call counter):** Moved from in-process storage (causing replication state flicker) to Redis `ai:metrics:calls:{YYYY-MM-DD}` with smart TTL strategy. 72 tests passing.

2. **#137 (Eval-403):** Initial pinning of agent-framework SDKs was necessary but insufficient. Real root cause was structural: commit 39dfdbe (P2 Wave 1 refactor #114) had dropped the per-transaction `eval_agent.run()` call and the resulting assistant `Message` turn from the eval payload. Foundry SDK's evaluators have nothing to score with an empty `response_text`, raisvc returns misleading 403. Fixed by restoring assistant turn.

## Outcomes

## Key Lessons

- Preview SDK pinning **is necessary** (prevents drift) but must be paired with **structural correctness** of the caller code
- Misleading error codes (403 for "missing response" instead of "unauthorized") make RCA much harder — file feedback with Microsoft
- Dead variables (`eval_agent` unused) are a code smell that regression introduced structural loss
